Whole-map investigation launched from the APM service map page. Activates when an observability.service-map-context attachment is present — it carries the user's map view filters (environment, kuery, time range, service group, highlighted services), not data. Surveys all services in scope for problems: active alerts, violated or degrading SLOs, ML anomalies, unusual error rates or latency between services, and isolated services with missing connections. Renders a service map attachment of the topology, explains the architecture (entry points, hubs, datastores, external dependencies) and links to the most problematic services and their alerts. Do NOT use for plain requests to visualize a service map without the context attachment — defer to service-map.
